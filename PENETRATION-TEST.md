# ProfitPilot — отчёт о локальной проверке безопасности

Дата: 11 августа 2026 года

Объект: локальная версия ProfitPilot 0.3

Метод: автоматизированные негативные API-тесты и ограниченная локальная имитация нагрузки.

## Проверенные сценарии

- SQL-инъекция в форме входа;
- объектная/NoSQL-подобная инъекция;
- инъекция в параметр маршрута;
- сохранённая XSS-нагрузка и политика CSP;
- CSRF с неверным токеном и запрос с чужого Origin;
- попытка обхода каталога и чтения `.env`;
- запрещённый метод TRACE;
- неверный Content-Type, повреждённый JSON и тело больше 5 MB;
- перебор паролей и срабатывание rate limiting;
- изоляция данных между организациями;
- 140 одновременных локальных HTTP-запросов;
- медленное незавершённое HTTP-соединение.

## Результат

Все четыре автоматизированных тестовых сценария пройдены. Инъекции и обходы не дали доступа к данным, CSRF и чужой Origin отклонены, перебор и лишний поток запросов ограничены. После локальной конкурентной нагрузки процесс продолжил работу, а отдельный статический маршрут остался доступен. Медленное соединение было закрыто сервером по тайм-ауту.

Команда повторного запуска:

```powershell
npm run check
npm test
```

## Границы проверки

Это контролируемая проверка приложения на одном компьютере, а не внешний профессиональный pentest и не объёмная DDoS-атака. Она не проверяет DNS, TLS, облачную сеть, reverse proxy, контейнеры, операционную систему, цепочку поставки и конфигурацию будущего production-хостинга. Перед публичным запуском требуются edge-защита CDN/WAF, мониторинг, проверка инфраструктуры и независимый тест с письменным разрешением и согласованными лимитами нагрузки.
